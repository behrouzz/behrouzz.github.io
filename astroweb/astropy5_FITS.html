FITS File Format

Flexible Image Transport System (FITS) is a very common file format in astronomy. It can store different types of data, including images and tables and a profide a greate way to store metadata. Astropy has a subpackage fits that can be used to read, modify and create FITS files.

Structure of a FITS file

We can open a FITS file using the open function from the fits subpackage. This function return a HDUList object. When we have finished working with the file, we can close it using .close() method. In the example below, we open a file named '656nmos.fits', see the type of object returned by the open function, then we close the file. The file of the example has been taken from this link:

https://esahubble.org/projects/fits_liberator/eagledata 
>>> from astropy.io import fits
>>> hdul = fits.open('656nmos.fits')
>>> type(hdul)
<class 'astropy.io.fits.hdu.hdulist.HDUList'>
>>> hdul.close()

What it the HDUList object? It is a list-like object that is a collection of another object named HDU. So, the creator of the FITS file, can put as many as HDUs he/she wants in the HDUList object, i.e., in the file. Howsever, each HDU can be of a different type. The first HDU in the file is alway of type PrimaryHDU. But the other HDUs can be in one of these types: ImageHDU, TableHDU, BinTableHDU or GroupsHDU. Each of these types define the nature of the data in that HDU. Let's see how many HDUs exist in our hdul variable in the above example and find the type of each HDU:

>>> len(hdul)
2
>>> type(hdul[0])
<class 'astropy.io.fits.hdu.image.PrimaryHDU'>
>>> type(hdul[1])
<class 'astropy.io.fits.hdu.table.TableHDU'>

You can see that there are two HDUs in our example file. The first one is of type PrimaryHDU and the second one is of type TableHDU.

Now, what is an HDU? The HDU stands for Header Data Unit. It means that it is a Unit that contains two parts: the Header part and the Data part. You can access each part of an HDU using .header and .data attributes. Let's see types of Header and Data parts of each of the HDUs in our example:

from astropy.io import fits
 
hdul = fits.open('656nmos.fits')

print(type(hdul[0].header))
print(type(hdul[0].data))
print(type(hdul[1].header))
print(type(hdul[1].data))

hdul.close()

Output:

<class 'astropy.io.fits.header.Header'>
<class 'numpy.ndarray'>
<class 'astropy.io.fits.header.Header'>
<class 'astropy.io.fits.fitsrec.FITS_rec'>

You can see that the Header part is always of type Header. But the Data part can be different depending on the nature of the data. In our example, the first HDU has the data of type numpy.ndarray, while the second HDU has the data of type FITS_rec. We'll see very soon what are each of these, but for now, let's introduce a usefull method that gives you an overal view of the file structre. The HDUList object has .info() method that prints the available HDUs in the file along with some caracteristics of each HDU.

from astropy.io import fits
hdul = fits.open('656nmos.fits')
hdul.info()
hdul.close()

Output:

Filename: 656nmos.fits
No.    Name      Ver    Type      Cards   Dimensions   Format
  0  PRIMARY       1 PrimaryHDU     290   (1600, 1600)   float32   
  1  656nmos.tab   1 TableHDU       353   1R x 49C   [D25.17, D25.17, E15.7, E15.7, E15.7, E15.7, ...]

The above output shows that our file has two HDUs. The first one is of type PrimaryHDU and the second one is of type TableHDU. You can see the name of each HDU, therir versions, their types, the number of cards in each HDU header, the dimensio of each HDU data and its format. Now, let's see what are Header and Data.

Header

The header of an HDU is a standard way of presenting some information about the data that exsits in that HDU. It is not the data itself, it is the metadata. Sometimes, the fisrt HDU has no data; in this case the header gives information about the whole file.

The header stores information in cards. A header can have any number of cards. In the example above, you can see that the header of the first HDU has 290 cards and the header of the second HDU has 353 cards. Let's see the first 10 cards of the header of the first HDU:

>>> hdul[0].header[:10]
SIMPLE  =                    T / FITS STANDARD                                  
BITPIX  =                  -32 / FITS BITS/PIXEL                                
NAXIS   =                    2 / NUMBER OF AXES                                 
NAXIS1  =                 1600 /                                                
NAXIS2  =                 1600 /                                                
EXTEND  =                    T / There maybe standard extensions                
BSCALE  =                1.0E0 / REAL = TAPE*BSCALE + BZERO                     
BZERO   =                0.0E0 /                                                
OPSIZE  =                 2112 / PSIZE of original image                        
ORIGIN  = 'STScI-STSDAS'       / Fitsio version 21-Feb-1996

Each line in the above results is a card. You can see that each card has three elements: keyword, value, and comment. For example, in the first card, SIMPLE is the keyword, T is the value and FITS STANDARD is the comment. You can also use the .cards attribute of the Header object to access the cards. Each card is represented by a tuple:

>>> hdul[0].header.cards[:10]
('SIMPLE', True, 'FITS STANDARD')
('BITPIX', -32, 'FITS BITS/PIXEL')
('NAXIS', 2, 'NUMBER OF AXES')
('NAXIS1', 1600, '')
('NAXIS2', 1600, '')
('EXTEND', True, 'There maybe standard extensions')
('BSCALE', 1.0, 'REAL = TAPE*BSCALE + BZERO')
('BZERO', 0.0, '')
('OPSIZE', 2112, 'PSIZE of original image')
('ORIGIN', 'STScI-STSDAS', 'Fitsio version 21-Feb-1996')

You can get or modify the value of a card if you pass its keyword as follow:

>>> hdul[0].header['ORIGIN']
'STScI-STSDAS'
>>> hdul[0].header['ORIGIN'] = 'Hubble'
>>> hdul[0].header['ORIGIN']
'Hubble'

If you want to save changes to disk, use the .writeto() method:

hdul.writeto('new_file.fits')

Header is not just some information for the user. It can also store information that may be used by the application or the package to know how to deal with the data. We will see it later.

Data

FITS files can store many kinds of data. So, while the header is always of type Header object, the data can be of different types. In most cases, the data may be a numpy array, a row of data or multiple rows.

In our example file, there are two HDUs. Let's explore the data of each HDU. The data of the first HDU is a numpy array with the shape 1600x1600. This is an image and we will late how to draw it:

>>> with fits.open('656nmos.fits') as hdul:
	print(type(hdul[0].data))
	print(hdul[0].data.shape)

	
<class 'numpy.ndarray'>
(1600, 1600)

The data type of the second HDU is FITS_rec. This is a subclass of numpy.recarray. One simple way to read this type of data in astropy is to pass it to Table objcet:

>>> from astropy.io import fits
>>> from astropy.table import Table
>>> hdul = fits.open('656nmos.fits')
>>> type(hdul[1].data)
<class 'astropy.io.fits.fitsrec.FITS_rec'>
>>> t = Table(hdul[1].data)
>>> print(t)
     CRVAL1            CRVAL2       CRPIX1 CRPIX2 ... MEANC200 MEANC300 BACKGRND
--------------- ------------------- ------ ------ ... -------- -------- --------
274.71149247724 -13.816384007183999  386.5  396.0 ... 114.3746 100.2731 42.37756
>>> hdul.clos()

You can also get the names of the columns using .columns attribute and get the value of a column as follow:

>>> hdul[1].data['CRVAL1']
array([274.71149248])

Displaying image in FITS file

Images are stored in FITS files as numpy arrays. So, they can be shown in the output in many different ways. The simplest way is to use the function imshow from matplotlib package. However, there's something that should be considered in this way. Some images are too dark to be visible when using imshow function. You may need to fix this using arguments vmin and vmax, or normalize values by providing a function, such as LogNorm(), to the norm argument. 

from astropy.io import fits
import matplotlib.pyplot as plt
from matplotlib.colors import LogNorm

hdul = fits.open('656nmos.fits')
img = hdul[0].data
hdul.close()

plt.imshow(img, cmap='gray', norm=LogNorm())
plt.show()

Well, that's good if you want to just view the image. The problem with the above image is the units of the axes: they are in pixels. When we plot a part of the sky, we expect the axes to be in astronomical coordiantes, such as RA and Dec. One great advantage of saving astronomical images in FITS format instead of JPG or PNG, is that we can save the projection data in the header of the HDU. But how can we read these information from the header?

This is what astropy does behind the scene with a subpackage named wcs. The World Coordinate Systems (WCS) manages geometric transformations between coordinates. In our case, we need a tranformation between pixels to celestial coordinates. The wcs subpackage has a WCS class. We should pass it the header of the HDU. Our image is in the first HDU, so we have to create an object as follow:

wcs = WCS(hdul[0].header)

This new object has now the nessessary information about the projection. We can pass it to matplotlib subplot function to get back an Axes object:

ax = plt.subplot(projection=wcs)

You can now use the imshow function as before to draw the image.

However, there's much we can to to customize the resulting image better. Now, ax has a new attribute .coords that will return a CoordinatesMap object. Put the coordinates components to access it like ax.coords['ra'] and ax.coords['dec']. If you want to customize the format of the axes, you can use .set_major_formatter method. For example to view RA in degree, arcminutes and arcseconds:

ax.coords['ra'].set_major_formatter('dd:mm:ss')

Another customization is to specify how many ticks and lines should apprear in the image. We can use .set_ticks method and specify the spacing between lines. For example if you want the lines to be drawn with 30 arcseconds between:

ax.coords['ra'].set_ticks(spacing=30 * u.arcsec)

The complete script is as follow:

from astropy.io import fits
from astropy.wcs import WCS
from astropy import units as u
import matplotlib.pyplot as plt
from matplotlib.colors import LogNorm
 
hdul = fits.open('656nmos.fits')
img = hdul[0].data
wcs = WCS(hdul[0].header)
hdul.close()

ax = plt.subplot(projection=wcs)

ax.coords['ra'].set_major_formatter('dd:mm:ss')
ax.coords['dec'].set_major_formatter('dd:mm')

ax.coords['ra'].set_ticks(spacing=30 * u.arcsec)
ax.coords['dec'].set_ticks(spacing=30 * u.arcsec)

plt.imshow(img, cmap='gray', norm=LogNorm())
plt.grid(color='lightblue', ls='dotted')
plt.xlabel('RA')
plt.ylabel('Dec')
plt.show()
