Astropy Time

Python comes with the standard module datetime which is very useful for dealing with date and time. There are two reasons that this module is not very suitable in astronomical calculations. First, datetime is just based on the civil calender. It stores and measures the time using year, month, day, hours, minutes, etc. In astronomy we use different time formats, such as Julian Date, Epoch, etc. Second, in astronomy, we use different Time Scales which make calculations much more complicated. This is why astropy introduces the time which has a very useful class Time.

To create a time object in astropy, you should create an instance of the Time class by passing:

  • the time value in one of the supported formats (as string, float or datetime)
  • the time format (datetime, 'iso', 'isot', 'jd', etc.)
  • the time scale ('utc', 'ut1', 'tt', 'tdb', etc.)

The time value can be a single value or an array of values. Usually, astropy can infer the format from the value you entered. So, the format argument is optional. The scale argument is also optional; it defaluts to 'utc'.

Time Format

Let's create a time object and check its value, format and scale.

>>> from astropy.time import Time
>>> t = Time('2021-03-20 09:37:11')
>>> t
<Time object: scale='utc' format='iso' value=2021-03-20 09:37:11.000>

Here, I entered the time value as a string in ISO format (YYYY-MM-DD hh:mm:ss) and astropy correctly infered the format as 'iso'. Since I did not determine the scale, astropy chosed the 'utc' scale.

We can enter the time value as python datetime. Let's see what is the difference between two time objects one with the ISO format and another with datetime format:

>>> from datetime import datetime
>>> t1 = Time('2021-03-20 09:37:11')
>>> t2 = Time(datetime(2021, 3, 20, 9, 37, 11))
>>> t1
<Time object: scale='utc' format='iso' value=2021-03-20 09:37:11.000>
>>> t2
<Time object: scale='utc' format='datetime' value=2021-03-20 09:37:11>

Since e did not enter the scale, both are 'utc'. The formats are different, but the values are the same. They point to the same ponit in time but with different formats. If we convert them to Julian Date using .jd attribute we will see that they have exactly the same value:

>>> t1.jd
2459293.9008217594
>>> t2.jd
2459293.9008217594

We can also change the format of a time object by modifing its .format attribute:

>>> t1.format = 'datetime'
>>> t1
<Time object: scale='utc' format='datetime' value=2021-03-20 09:37:11>
>>> t2
<Time object: scale='utc' format='datetime' value=2021-03-20 09:37:11>

Now, both t1 and t2 are identical.

It is a good practice to explicitly determine format and scale. We'll talk about scale later. For now, let's create a time object with a numerical value as Julian Date:

>>> t = Time(2459293.9008217594, format='jd')
>>> t
<Time object: scale='utc' format='jd' value=2459293.9008217594>

We can get the ISO version using the .iso attribute, or we can change the format of the time object by modifying the .format attribute:

>>> t.iso
'2021-03-20 09:37:11.000'
>>> t.format = 'iso'
>>> t
<Time object: scale='utc' format='iso' value=2021-03-20 09:37:11.000>

You can check all of the supported time formats using Time.FORMATS.

Time Scale

To check which time scales are supported by astropy:

>>> Time.SCALES
('tai', 'tcb', 'tcg', 'tdb', 'tt', 'ut1', 'utc', 'local')

Let's create a time object with Terrestrial Time (TT) scale and convert it to other time scales:

>>> t = Time('2021-03-20 09:38:20.184', scale='tt')
>>> t.utc
<Time object: scale='utc' format='iso' value=2021-03-20 09:37:11.000>
>>> t.ut1
<Time object: scale='ut1' format='iso' value=2021-03-20 09:37:10.828>
>>> t.tai
<Time object: scale='tai' format='iso' value=2021-03-20 09:37:48.000>
>>> t.tdb
<Time object: scale='tdb' format='iso' value=2021-03-20 09:38:20.186>

The difference between UT1 and UTC is called \(\Delta UT\). It is it is expressed in seconds and we can get it using .delta_ut1_utc attribute. Behind the scene, astropy retrieves this value from the International Earth Rotation and Reference Systems Service (IERS). Likewise, the difference between TDB and TT is called \(\Delta TR\) and we can get it with .delta_tt attribute.

>>> t = Time('2021-03-20 09:38:20.184', scale='tt')
>>> print(t.delta_ut1_utc)
-0.17189276191666666
>>> print(t.delta_tdb_tt)
0.001618808591149933

Let's finish this section with an example. As said before, the value of a time object can be single or an array. Here, we want to measure the length of the calendar years between 2015 and 2024. So, we create a time object by passing the first day of january of each of the years as an array. Then, we substract each year from the year after it. By substracting a time object from another time object, we get a TimeDelta object. By default, the scale is TAI and the format is Julian Date. 

import numpy as np
from datetime import datetime
from astropy.time import Time

years = np.arange(2015, 2025)
arr = [datetime(y, 1, 1) for y in years]

t = Time(arr, scale='utc')

dt = t[1:] - t[:-1]

print('Scale :', dt.scale)
print('Format:', dt.format)

for i,j in zip(years[:-1], dt.value):
    print(i, ':', j)

Output:

Scale : tai
Format: jd
2015 : 365.00001157407405
2016 : 366.00001157407405
2017 : 365.0
2018 : 365.0
2019 : 365.0
2020 : 366.0
2021 : 365.0
2022 : 365.0
2023 : 365.0

The years 2016 and 2020 were leap years, so they had 366 days. But what is the number .00001157407405 added to the years 2015 and 2016? This is one second expressed in Julain Date format. In fact, it is the result of 1/86400. One leap second has been added to each of the years 2015 and 2016 by the IERS to keep UTC and UT1 close to each other.
