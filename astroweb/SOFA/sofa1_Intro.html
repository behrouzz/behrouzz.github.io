Introduction to SOFA

Every program that points a telescope, predicts a planet or converts the coordinates of a star has to do the same careful calculations: change the time scale, remove the effect of precession and nutation, apply aberration, take the rotation of the Earth into account, and so on. If every astronomer writes these formulas again, mistakes are certain, and two programs will not give exactly the same answer. This is the problem that SOFA solves.

What is SOFA?

SOFA stands for Standards of Fundamental Astronomy. It is a collection of software, produced and maintained by an IAU SOFA Board that works under the International Astronomical Union (IAU). Its functions implement the algorithms that the IAU has officially adopted for fundamental astronomy. This includes the time scales, the models for the precession and nutation of the Earth's axis, the rotation of the Earth, the transformations between celestial reference systems and many others. The library is carefully tested, and it is widely used as a reference by observatories and other software packages.

The SOFA library has roughly 190 functions of astronomy and about 55 smaller functions for angles, vectors and matrices. They are published in two versions that are written in C and in Fortran. The documentation is made of the comments in the source code of each function, plus a few tutorials called cookbooks, each about one subject. The tutorials in this chapter are based on these cookbooks.

SOFA in Python: pyerfa

Python programs cannot call the C or Fortran functions directly. In this tutorial we use a Python implementation that is called pyerfa. It is a thin wrapper around ERFA (Essential Routines for Fundamental Astronomy), a C library that was derived from SOFA with a permissive open-source license. The algorithms and the numerical results are those of SOFA. To avoid any confusion with the official library, the names are different: the prefix iau of the C functions is not used in ERFA (which uses era), and pyerfa drops the prefix completely. The astropy package uses pyerfa internally for its Time and coordinates classes (see the chapters about Time and Coordinates), and now you will see the same functions at work without the layers around them.

It is installed with:

pip install pyerfa

and it is imported with import erfa. Let us check that it works and which versions we have:

import numpy as np
import erfa

print("pyerfa", erfa.__version__, "- ERFA", erfa.version.erfa_version)
pyerfa 2.0.1.5 - ERFA 2.0.1

How to read the SOFA documentation

All the SOFA documents are written for the C version, so the first step is to translate the names. The rule is simple: drop the prefix iau and write the rest in lowercase.

SOFA (C)pyerfa
iauDtf2derfa.dtf2d
iauAtco13erfa.atco13
iauC2t06aerfa.c2t06a
iauRxrerfa.rxr
DAS2R, DD2R, DR2D, ... (constants)erfa.DAS2R, erfa.DD2R, erfa.DR2D, ...

If you cannot find a function in pyerfa, list the available names with dir(erfa). (Do not forget that a few SOFA functions that read or write files, or that are not astronomy, do not exist in ERFA.)

In C, a function takes its inputs as arguments and also gives its results by arguments (pointers). In Python the results are simply returned, in the order in which they appear in the C documentation. For instance, in C you write iauAtci13(rc, dc, pr, pd, px, rv, date1, date2, &ri, &di, &eo), and in Python:

ri, di, eo = erfa.atci13(rc, dc, pr, pd, px, rv, date1, date2)

Conventions used by all functions

  • Angles are in radians. The constants erfa.DR2D (radians to degrees), erfa.DD2R (degrees to radians), erfa.DAS2R (arcseconds to radians) and erfa.DMAS2R (milliarcseconds to radians) help to convert them.
  • Julian dates have two parts. A date is given as two numbers whose sum is the Julian date, to keep full numerical precision (more in the chapter about time).
  • Positions are unit vectors or 3-vectors (NumPy arrays), rotations are 3×3 matrices.
  • Everything is vectorized. The functions of pyerfa are NumPy universal functions: you can give them arrays instead of numbers, and they return arrays. A million stars can be transformed in a single call.
  • Problems are reported with exceptions and warnings. The C functions return a status code. In pyerfa, a serious problem (for example an impossible date) raises an erfa.ErfaError and a doubtful result (for example a date for which the leap second table is not reliable) gives an erfa.ErfaWarning.

The last point in action:

import warnings

# an impossible date raises an error
try:
    erfa.dtf2d("UTC", 2010, 13, 1, 0, 0, 0.0)
except erfa.ErfaError as error:
    print("Error:  ", error)

# a doubtful result gives a warning (UTC did not exist in 1800)
with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    value = erfa.dat(1800, 1, 1, 0.0)
print("Warning:", caught[0].message)
Error:   ERFA function "dtf2d" yielded 1 of "bad month"
Warning: ERFA function "dat" yielded 1 of "dubious year (Note 1)"

A first example

Let us do something real: how much has the Earth turned at the beginning of the year 2000? The Earth Rotation Angle (ERA) is the angle of the Earth's rotation with respect to the stars, and it depends on the UT1 time only. We encode a date, call era00 and convert the result to hours:

# 2000 January 1, 12:00:00 UTC (the epoch J2000.0 is 2000 January 1.5)
utc1, utc2 = erfa.dtf2d("UTC", 2000, 1, 1, 12, 0, 0.0)

# for this tutorial we pretend that UT1 = UTC (they differ by less than a second)
era = erfa.era00(utc1, utc2)
print(f"Earth rotation angle: {era * erfa.DR2D:.6f} degrees = {era * erfa.DR2D / 15:.6f} hours")
Earth rotation angle: 280.460618 degrees = 18.697375 hours

The Earth rotation angle was about 280.46° at that moment. The exact UT1 would change the last digits only a little.

FAWS: the Swift implementation

The author of this tutorial, Behrouz Safari, has also created a Swift implementation of SOFA, named FAWS (Fundamental Astronomy With Swift). It is a Swift package with the same set of functions, so that the SOFA algorithms can be used in iOS and macOS applications and in any Swift program. It is available on GitHub and its documentation (with the list of functions and examples) is at behrouzz.github.io/faws. Some of the examples of this tutorial come from that documentation: here they are translated to Python, which is the language of the rest of the tutorials.

The plan of this chapter

The next five pages follow the five SOFA cookbooks. They go from simple to complex, because each topic uses the one before it:

  1. Vector-Matrix Library: angles, vectors and rotation matrices, the language of all the other functions.
  2. Time Scale and Calendar Tools: calendars, Julian dates and the seven time scales (UTC, TAI, UT1, TT, TCG, TCB, TDB).
  3. Tools for Earth Attitude: precession, nutation, Earth rotation and polar motion. How to go from the celestial to the terrestrial frame.
  4. Astrometry Tools: the complete chain from the catalog entry of a star to the direction where a telescope must point.
  5. Miscellaneous Topics: ecliptic and galactic coordinates, older catalogs (FK4, FK5, Hipparcos), the shape of the Earth and simple ephemerides.

A good order is the one above, but if you only want to convert the coordinates of stars, you can go directly to the Astrometry chapter and come back to the others when you need to understand a detail.
