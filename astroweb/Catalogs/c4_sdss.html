Sloan Digital Sky Survey

The Sloan Digital Sky Survey (SDSS) is one of the greatest deep-sky surveys ever made. It has been launched by Apache Point Observatory in New Mexico, United States.

Explan here....

The most basic types of data collected by the SDSS are photometric and spectroscopic data. The photometric data have been collected by a special type of camera that is equipped with 30 CCDs arranged in six columns and five rows. Each row of the camera uses a different filter, from ultraviolet to infrared. These bands are u, g, r, i and z.

NAME u g r i z
COLOR Ultraviolet Green Red Near-Infrared Infrared
WAVELENGTH 3543 4770 6231 7625 9134

The process of scanning the sky occurs with very slow movement of the camera along its columns. Therefore, the CCDs in each column capture the same image but in five different filters.

SDSS terminology

A strip is a scan along a line of constant survey latitude. The fraction of a strip observed at one time is a run. A camcol (camera column) is the output of one camera column of CCDs as part of a Run. A field is a part of a camcol that is processed by the Photo pipeline at one time. Fields are 2048 × 1489 pixels; a field consists of the frames in the 5 filters for the same part of the sky. For a brief description see here and for a more technical description see here.

If you have run, camcol and field of an image, you can see it via a tool called Get Fields. But we may not always know these parameters.

The SDSS team has assigned a unique ID to each object scanned in the sky called ObjID. If you know already the ObjID of an object, you can find some of the parameters mentioned above by the underlying SDSS ObjID Encoding that has been implemented in decode_objid function of sdss python package. It can be installed as follows:

pip install sdss
For example, we want to find the parameters of an object whose ObjID is 1237648720693755918:

import sdss
dc = sdss.decode_objid(1237648720693755918)
print(dc)

Output:

{'version': 2,
 'rerun': 301,
 'run': 756,
 'camcol': 2,
 'first_field': 0,
 'field': 427,
 'id_within_field': 14}

TAP Queries

The most advanced way of retriving tabular data from SDSS server is using SQL queries. We will cover non-tabluar data, such as images and spectra, later in this chapter. To retrieve tabular data, you can write SQL queries directly in the SQL Search page directly, or if you prefer astroquery, you can use query_sql or query_sql_async functions from the astroquery.sdss subpackage. Anyway, you should use the Schema Browser to find tables from which you want to retrieve data and their columns. There are a lot of tables, views and functions defined in the database. We will only explain a few of them.

The photometric objects are stored in PhotoObjAll table and PhotoObj view. In most cases, you should prefer PhotoObj because it is the same as PhotoObjAll except that it excludes duplicates. Views are precomputed tables and are usualy more user-friendly. So, we recommend using PhotoObj view when you need photometric objects. Each object in this table is identified by objID column.

Each object has been photographed in an image that can be identified by four numbers: run, rerun, camcol and field. These are available as columns of PhotoObj table. Other important columns of this table are: coordinates columns, such as ra and dec, time of observation as mjd, magnitudes in the five bands as u, g, r, i, z. If the object has spectrum, the column specObjID will show a pointer to the spectrum of the object, otherwise it is zero.

from astroquery.sdss import SDSS

query = """
SELECT TOP 5 objID, ra, dec, g, r, i
FROM PhotoObj
"""

table = SDSS.query_sql(query)
table.pprint()

The spectro objects are stored in specObjAll table and SpecObj view. In most cases, we prefer using SpecObj because it only contains spectro objects that have clean spectra and excludes duplicates. Each object these tables is identified by specObjID column. There is one column in this table that helps you join it to PhotoObj table: bestObjID. An spectro object can be identified by three numbers: plate, mjd and fiberID. These are available as columns of SpecObj table. Other important columns of this table are: coordinates columns, such as ra and dec, redshift as z, spectroscopic class as class (GALAXY, QSO, STAR) and spectroscopic subclass as subClass. from astroquery.sdss import SDSS

query = """

If you want some data from PhotoObj and SpecObj at the same time, you can join them. As a simple example, let's say we want the magnitude in g band and redshif z for all objects with magnitudes between 0 and 9.5. You can use this SQL query:

SELECT ph.objID, sp.specObjID, ph.g, sp.z
FROM PhotoObj as ph
JOIN SpecObj AS sp
ON ph.objID = sp.bestObjID
WHERE ph.g BETWEEN 0 AND 9.5

It works, but there is a better solution which is more efficient and more rapid. There is another useful view named SpecPhoto. This is the table of joined Spectro and Photo objects that have the clean spectra. So, instead of the above query, we can use this one:

from astroquery.sdss import SDSS

query = """
SELECT objID, specObjID, modelMag_g, z
FROM SpecPhoto
WHERE modelMag_g BETWEEN 0 AND 9.5
"""

table = SDSS.query_sql(query)
table.pprint()

Cone search

One common search is retriving data from a region in the sky. Suppose that we want to get all photometric objects in a region with radius 1 arcmin:

>>> import astropy.units as u

Downloading images

The SDSS class provides the function get_images to download images. When we say image, we mean the smallest cadre that has been photographed. It is a filed and as explanied earlier, is identified by three parameters: run, camcol and field numbers. So you can pass these numbers to the the function get_images to get the image as a list of HDUList objects. For example, to get the image that contains the first object in the tbl_phot table of the example above, we can do as follows:

>>> images = SDSS.get_images(run=3918, camcol=3, field=213)
>>> len(images)
1
>>> type(images[0])
<class 'astropy.io.fits.hdu.hdulist.HDUList'>

Since we provided all of the three parameters that identify an image, the function get_images return a list that has only one HDUList object. If we omit one of these parameters, the function will return all possible images. You can provide the band argument to specify that you want the image in which band. If you dont specify it, as we did not in this example, the image for the 'g' band will be downloaded.

Now, let's look at the HDUList object.

>>> hdul = images[0]
>>> hdul.info()
Filename: (No file associated with this HDUList)
No.    Name      Ver    Type      Cards   Dimensions   Format
  0  PRIMARY       1 PrimaryHDU      96   (2048, 1489)   float32   
  1                1 ImageHDU         6   (2048,)   float32

  3                1 BinTableHDU     79   1R x 31C   [J, 3A, J, A, D, D, 2J, J, D, ... D, D, D, D, E, E]

The image is in the PrimaryHDU. So, we can access it using .data attribute:

>>> img = hdul[0].data

We can simply save the image as a FITS file as follows:

hdul.writeto('my_sdss_image.fits')

Image cutouts

So far, we have seen how to download a images. Note that an image is a single field that contains many objects. Sometimes you need exactly the photo of an object, not the entire filed it belongs to. What we want here, is to obtain a picture centered on our desired coordinates with our desired fields of view (fov). SDSS has provided an API to retrieve image coutouts. I have already implemented it in the sdss python package. For this reason you can create an instance of the Region class by passing the coordinates, your desired width and length in pixels and your desired field of view in degrees.

from sdss import Region

reg = Region(ra=229.52569, dec=42.74472, width=300, height=300, fov=0.033, opt='')

reg.show()

Output:

I passed an empty string to the opt argument because I did not want any extra marks on the image cutout. Refer to SDSS API help for all possible values.

Using the image cutout API is a good idea for simple tasks. If you want to obtain image cutouts of many object in a field, a better idea is to first download that filed as a FITS file (as we did before), then find each object in that image. There is one important question here: Even in a FITS file, the images is given as a numpy array. How can we find the location of an object in the numpy array.

When an image is represented by a numpy array, any point is represented by a pixel. So, the coordinates of the point is in terms of row and column. But, here, we only know the celestail coordinates, as RA and DEC, not pixel row and column. This is where the subpackage wcs from astropy can help us. We have seen before that we can create an instance of WCS class by passing the header of the primary HDU of the FITS file. This instance of WCS is a powerful object that helps us to convert the celectial coordinates to pixel coordinates, using world_to_pixel method. To use this mthod, simply give it he celectial coordinates and it will return its pixel equivalent in that image.

from astropy.io import fits
from astropy.wcs import WCS
from astropy.coordinates import SkyCoord

hdul = fits.open('my_sdss_image.fits')
img = hdul[0].data
wcs = WCS(hdul[0].header)
hdul.close()

c = SkyCoord(ra=229.52869, dec=42.73472, unit='deg')

x, y = wcs.world_to_pixel(c)
x, y = round(float(x)), round(float(y))
d = 150

cutimg = img[x-d:x+d, y-d:y+d]

In the above example, x and y are row and column of the pixel that corresponds c. Now that we found the pixel location of our point, we can simply slice the image as we wish.

Downloading spectra

SDSS collects two major types of spectra: one-dimensional and two-dimensional. Here, I'm going to talk about the 1D spectra.

The spectrum of an object can be identified with three numbers: Plate, MJD and FiberID. The reason behind these numbers is that the SDSS records spectra using aluminum plates placed at focal plane of the telescope. Each plate has a unique plate number and it is connected to the spectroscope via 1000 optical fibers. Each optical fiber transmits the light of one object to the spectroscope and is identified by a unique fiber_id. The date at which the spectrum has been recorded is identified with mjd, which is the Modified Julian Date.

Another way that SDSS identifies the spectrum of an object is by an identifier number, called SpecObjID. If you know SpecObjID of an object, you can find the above mentioned parameters using decode_specid function of sdss python library:

import sdss
dc = sdss.decode_specid(320932083365079040)
print(dc)

Output:

{'plate': 285, 
 'fiber_id': 184, 
 'mjd': 51930, 
 'run2d': 26}

Note that SpecObjID is different from ObjID. We should use ObjID when we need the photometric data of an object, and SpecObjID for spectrometric data. In fact, the number of photometric objects are much higher than spectrometric objects. It means that for most of the objects, there is no spectrometric data.

In astroquery, the SDSS class provides the function get_spectra to download spectrum. This function accepts multiple arguments and you have three ways to use it:

  • pass values to plate, mjd and fiberID arguments
  • pass values to coordinates and radius arguments
  • pass returned table resulted from calling query_region to matches argument

Note that in the first method, only one spectrum will be retrieved, but the second and third methods may retrieve spectra for several objects. In any case, the function get_spectra will return a list of HDUList objects. Let's try the first method and retrieve a single spectrum. We will take a look at it and save the retrived object as a FITS file.

from astroquery.sdss import SDSS

sp = SDSS.get_spectra(plate=285, mjd=51930, fiberID=184)

hdul = sp[0]
hdul.info()

hdul.writeto('my_sdss_spec.fits')

You can see that the table contains eight columns. The wavelengths are stored in the loglam column in logarithmic scale. The flux column is the raw flux data as recorded by the spectrometer, and the model column is the result of the best fitted model on the flux. In many cases we prefer to use model instead of flux.

The loglam column is in logarithmic scale, so, to extract the wavelengths in Angstrom (AA) we should raise ten to power of these numbers. The unit of flux as used is SDSS spectra is in:

\[ 10^{-17}\cdot erg\cdot cm^{-2}\cdot s^{-1}\cdot AA^{-1} \]

Let's recreate these variables with their appropriate units:

>>> t1['wavelength'] = 10 ** t1['loglam'] * u.Unit('AA')
>>> t1['model'] = t1['model'] * 10**-17 * u.Unit('erg cm-2 s-1 AA-1')
>>> t1[['wavelength', 'model']].pprint(max_lines=10)

You can use the .columns attribute to see all of the columns available in the table of this HDU. Let's find class, subclass and redshift of the object:

Note that the area of some lines is zero. It means that these line do not appear on the spectrum. You may want to draw the lines on the plot of spectrum. For this reason, we should calculate the observed lines. According to the definition of redshift:

\[ \lambda_{obs} = \lambda_{rest}(1+z) \]

Using this formula, we can calculate the observed wavelength of the lines easily. But first let's get rid of the lines with zero area:

>>> t3 = t3[t3['LINEAREA']!=0.0]
>>> t3['obs'] = t3['LINEWAVE'] * (1 + t3['LINEZ'])

Finally, to finish this section and as a review, let's draw the plot of the spectrum with the emmision lines. To better see the lines, we limit the plot for wavelengths between 7100 to 7500 Angstrom. By deleting plt.xlim, you can draw the full plot or by changing the limit you can zoom on any part of the spectrum.
